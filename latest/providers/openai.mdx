AI-Implement can run the Codex agent against OpenAI. Each OpenAI account profile authenticates one of two ways: an OpenAI API key, or a ChatGPT plan you connect from your own account.

Both are configured per account profile on the **Models & providers** page of the admin UI. Set up the profile first, then add a key or connect a plan to it.

## Before you start

The account profile form, **Set key**, and **Connect ChatGPT plan** show only for the `admin` role. With the `user` role, **Models & providers** is read-only.

An admin grants the role on the **Access** panel (`/admin#access`). Only a listed email address can be made `admin`, and a domain entry always admits as `user`.

<Warning>
  AI-Implement does not read an `OPENAI_API_KEY` environment variable. A key reaches a run only through **Set key** on its account profile, with no environment fallback.
</Warning>

## Choose how to authenticate

The two methods differ in billing and what each needs:

|  | OpenAI API key (`openai-api-key`) | ChatGPT plan (`codex-subscription`) |
|---|---|---|
| Billing | The OpenAI API platform, separate from any ChatGPT subscription | The connected plan's Codex limits |
| Use for | Customer-facing runs | Your own plan only, never shared |
| Needs | An API organization with credits | A ChatGPT plan with Codex, and a laptop with an AI-Implement checkout |

## Get an OpenAI API key for a business

This section applies to the OpenAI API key path. Skip it if you are connecting a ChatGPT plan.

A ChatGPT Business subscription (formerly ChatGPT Team) does not include API usage. The API organization on [platform.openai.com](https://platform.openai.com) is separate from the ChatGPT workspace.

The organization selector at the bottom left of [platform.openai.com](https://platform.openai.com) often shows one organization named **Personal**. It belongs to the login you signed in with, so it can serve as your company's organization.

You cannot create a second organization yourself. OpenAI support creates one on request, and OpenAI recommends projects within a single organization instead.

<Steps>
  <Step title="Add billing or prepaid credits">
    Add a payment method or prepaid credits before anything else. While the **Add credits** panel still shows, every request fails with a quota error.
  </Step>
  <Step title="Create a project">
    Create a project — for example `ai-implement`. The **Default project** cannot hold service accounts, so a dedicated project is required.
  </Step>
  <Step title="Set the project's limits">
    Under the project's **Limits**, restrict **Model usage** and set a **Monthly spend limit**.
  </Step>
  <Step title="Create a service-account key">
    Under the project's **Members**, choose **+ Service account** and create the key. The key is shown once, so copy it immediately.
  </Step>
  <Step title="Note the key's expiry">
    Record the key's **Expires** date. After it passes, the profile stops working until you set a new key.
  </Step>
</Steps>

For what OpenAI documents on each step, see:

- [Managing projects in the API platform](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform)
- [Managing billing for ChatGPT and the API platform](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)
- [Requesting an additional API organization](https://help.openai.com/en/articles/8991840-requesting-an-additional-api-organization)

## Account profiles

An account profile pairs a set of credentials with the projects allowed to use them. Create one on **Models & providers** with **Add account profile** before you add a key or connect a plan.

The form has these fields:

- **Profile ID** — a stable, lowercase identifier for the profile. An uppercase letter makes **Set key** fail later, so keep it lowercase.
- **Identity** — a label that identifies the account to operators.
- **Agent** — `codex`.
- **Provider** — `openai`.
- **Authentication** — `openai-api-key` for an API key, or `codex-subscription` (shown as **ChatGPT plan**) to connect a ChatGPT plan.
- **Permitted projects** — the projects this profile may serve, set as described in [Permitted projects](#permitted-projects).

**Agent**, **Provider**, and **Authentication** must form one of these combinations, or the save is refused with `profile agent/provider/authentication combination is unsupported`:

- `codex` + `openai` + `openai-api-key` or `codex-subscription`
- `claude` + `anthropic` + `anthropic-api-key` or `claude-subscription`
- `claude` + `bedrock` + `bedrock`

A new profile is created **active**. A ChatGPT plan can only be connected while the profile is active.

### Permitted projects

**Permitted projects** controls which projects a profile may serve:

- **Blank** — serves every project. The field is stored as `*` and shown in the table as `all projects`.
- **A comma-separated list of project keys** — serves only those projects.
- **Emptied after being set** — serves no project. Empty the list with `PATCH /api/model-accounts/:id`, or disable the profile, to revoke access.

<Note>
  Readiness is checked against one permitted project. A profile with a list is checked against its first key, and an all-projects profile is checked against a mapped project. A profile with an emptied list has no project to probe and shows **unknown** readiness — a missing probe target, not a rejected credential.
</Note>

## Use an OpenAI API key

<Steps>
  <Step title="Add a codex / openai profile">
    Create an account profile as described in [Account profiles](#account-profiles), with **Authentication** set to `openai-api-key`.
  </Step>
  <Step title="Set the key">
    In the profile's row, enter the key and click **Set key**.

    The key is write-only: it is encrypted on save and never shown again. The **API key** column then reads **set**, and an empty profile reads **not set**.
  </Step>
  <Step title="Replace or remove the key">
    To replace the key, enter a new value and click **Set key** again — the new value overwrites the old one.

    To clear it, click **Remove key**.
  </Step>
</Steps>

## Connect a ChatGPT plan

Connecting a ChatGPT plan signs you in with your own ChatGPT account. **It is for personal and self-hosted use of your own plan** — do not use it to pool, share, or resell plan access. For customer-facing OpenAI runs, use an API key instead.

Pairing is the normal path: the admin UI mints a code, and a helper on your laptop signs in and uploads the result. You will need:

- **A laptop with a web browser.** Sign-in opens a browser and completes through a loopback (`127.0.0.1`) callback, so the browser and the command must run on the same machine. A remote orchestrator cannot receive that callback.
- **An AI-Implement source checkout on that laptop, built with `npm run build`**, so the sign-in helper is available.

<Steps>
  <Step title="Add a ChatGPT plan profile">
    Create an account profile as described in [Account profiles](#account-profiles), with **Authentication** set to `codex-subscription` (shown as **ChatGPT plan**). The profile must be **active**.
  </Step>
  <Step title="Start pairing">
    In the profile's row, click **Connect ChatGPT plan**. The admin UI shows a single-use pairing code and the laptop command to run, both shown once.
  </Step>
  <Step title="Run the command on your laptop">
    From your AI-Implement checkout, run the command the admin UI showed:

    ```bash
    node dist/chatgpt-plan-login.js connect --orchestrator https://<orchestrator-host> --record ~/.ai-implement/chatgpt-plan.json
    ```

    The command asks for the pairing code at a hidden prompt. Type it there, so it never goes on the command line.

    It then opens your browser to sign in with ChatGPT and uploads the signed-in record to the orchestrator.

    Once the upload succeeds, the helper removes the tokens from the laptop so the orchestrator holds the only copy. It does this without revoking them, so there is nothing to sign out on the laptop.

    Do not revoke the hosted session to "sign out" the laptop after a successful pairing — that would break the orchestrator's copy too.
  </Step>
  <Step title="Confirm the connection">
    Back in the admin UI, click **Check status** to see the connected account and the latest refresh result.
  </Step>
</Steps>

<Warning>
  The pairing code works once and expires 15 minutes after it is shown. A rejected upload — a bad record, the wrong profile state, or an oversize record — still spends the code, so if the command fails, click **Connect ChatGPT plan** again to mint a fresh one.
</Warning>

If the command uploads the record but you never see a confirmation — a dropped connection after the orchestrator accepted it — the orchestrator may already own the sign-in while the laptop still holds the same tokens.

Delete the leftover record file at `~/.ai-implement/chatgpt-plan.json`, and do nothing else to it. Do not sign in, refresh, or reuse it on the laptop, which would make the orchestrator's copy look reused.

<Warning>
  Do not run `logout` to clear the leftover record. Local logout revokes the refresh token, and the orchestrator may hold the same one, so it can disconnect the hosted session. Delete the file instead.
</Warning>

Then click **Check status** to see whether the orchestrator is connected. If it is connected, you are done. If it is not, click **Connect ChatGPT plan** again and run the command with a fresh code.

### Manual import and host sign-out

You can also sign in on the laptop and import the record to the orchestrator by hand, then sign a connected account out from the host.

<Steps>
  <Step title="Sign in on the laptop">
    ```bash
    node dist/chatgpt-plan-login.js login --record ~/.ai-implement/chatgpt-plan.json
    ```

    This opens your browser and saves a signed-in record to the path you give.
  </Step>
  <Step title="Import the record to the orchestrator">
    Pipe in the same record file the previous step wrote:

    ```bash
    fly ssh console -a <orchestrator-app> -C "node dist/model-account-cli.js chatgpt-import --profile <profile-id>" < ~/.ai-implement/chatgpt-plan.json
    ```

    The record travels over stdin, never on the command line. Delete the laptop record file afterward.
  </Step>
</Steps>

Sign a connected account out from the host, which revokes the token at OpenAI and stores a record with no tokens. It works even on a disabled or archived profile, so you can revoke a retired account's session:

```bash
fly ssh console -a <orchestrator-app> -C "node dist/model-account-cli.js chatgpt-logout --profile <profile-id>"
```

Read the connected account and the refresher's last outcome from the host — it never prints a token:

```bash
fly ssh console -a <orchestrator-app> -C "node dist/model-account-cli.js chatgpt-status --profile <profile-id>"
```

Inspect the laptop's own record with the local `status` command, which prints the account and time left:

```bash
node dist/chatgpt-plan-login.js status --record ~/.ai-implement/chatgpt-plan.json
```

The local `logout` command revokes the refresh token and clears the local tokens:

```bash
node dist/chatgpt-plan-login.js logout --record ~/.ai-implement/chatgpt-plan.json
```

Use local `logout` only on an independent laptop-only sign-in — one you created with `login` and never uploaded or imported. Once the orchestrator holds the same sign-in, revoking it on the laptop disconnects the hosted session too. To sign out a hosted account on purpose, use the host sign-out command above instead.

## Next: point the project at the profile

Creating a profile and setting its credential enrolls no project on its own. Opt the project in on its **Agents** tab (**Projects → Edit → Agents**), where every stage needs a resolved account profile.

See [Agent settings per stage](/latest/configuration/agents) for opt-in and the per-stage rules.

## Moving off the GitHub Actions Claude review

Switching a project from the GitHub Actions Claude review to AI-Implement's internal review with Codex takes two separate settings:

- **Review process** (on the project) decides who reviews the pull request and fixes the findings. Change it from **Claude Code Review** (`claude-code-review`) to **AI-Implement** (`ai-implement`) to hand review to AI-Implement's own reviewers.
- **Review stage** (on the **Agents** tab) decides which agent and model the internal review runs. Choose `codex` with a Codex account profile there for Codex to review.

Changing the review process alone keeps Claude as the reviewer, because the review stage still selects the agent that runs.

See [Review process](/latest/customize/external-reviewers#review-process) for the review-process values and [Agent settings per stage](/latest/configuration/agents) for the review stage.

## How stored credentials are protected

The orchestrator stores both API keys and connected ChatGPT plans encrypted, under a key derived from the `RUNNER_TOKEN_SECRET` that every hosted deployment already sets. No extra variable is involved.

<Warning>
  Rotating `RUNNER_TOKEN_SECRET` makes every stored credential unreadable, and nothing on the orchestrator can recover the old ones. After a rotation, set each API key again and reconnect or re-import each ChatGPT plan.
</Warning>

No token value should ever appear in a command argument, an example, a Git commit, or any published artifact:

- The pairing code is typed at a hidden prompt and travels only in a request header, never on the command line.
- API keys are write-only in the admin UI and are never shown after you save them.
- The sign-in, status, and import commands never print a token.

Connect a ChatGPT plan with the sign-in helper above — do not try to reuse a Codex `auth.json` file.
