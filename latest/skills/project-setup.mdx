The `bd-` skills reach your issues and repositories through a pair of connectors: your **orchestrator** and your **ticketing system**. You add each one once per account at [claude.ai/settings/connectors](https://claude.ai/settings/connectors).

There is nothing to set up per project. Every skill reads its project mappings from the orchestrator at the start of each session, so a fresh checkout needs no `.mcp.json` entry and no binding file — signing in with the account that holds the connectors is enough.

<Info>
  This assumes the skills are already installed. If not, [start with installation](/latest/skills/installation) first.
</Info>

## Connect your services

<Steps>
  <Step title="Allow the claude.ai callback origin on your orchestrator">
    Before a custom connector can authenticate, the orchestrator has to allow the claude.ai callback origin:

    ```bash
    fly secrets set MCP_ALLOWED_REDIRECT_ORIGINS=https://claude.ai,https://claude.com --app <your-app>
    ```

    <Warning>
      Set this first. A connector rejected with `invalid_redirect_uri` before the sign-in screen appears is missing this origin.
    </Warning>
  </Step>

  <Step title="Add the connectors">
    In [claude.ai/settings/connectors](https://claude.ai/settings/connectors), add a custom connector for each service:

    - your **orchestrator** — the AI-Implement service that holds your project mappings and picks up marked issues to open pull requests
    - your **ticketing system** — Linear or Jira, where your issues live

    Add each one once per account, from the web. Connectors are added and removed from the web, and enabled or disabled per session from the mobile app.
  </Step>

  <Step title="Sign in to Claude Code">
    The connectors load automatically in Claude Code when you sign in with the same account.

    No project `.mcp.json` entry is needed.

    <Check>
      At the start of a session, the skills print:

      - the orchestrator they resolved
      - the project binding they read
      - the tracker they checked

      Setup is complete once those lines name your services.
    </Check>
  </Step>
</Steps>

## One tracker connector, one workspace

A tracker connector is signed into one workspace at a time.

When a repository's mapping expects a different workspace, the session-start check names the connector to reconnect to.

To work in another workspace, reconnect the tracker connector to it rather than editing any project file.

<Note>
  Linear is supported across the whole suite. Jira works, but some skills describe it in terms projected from their Linear behavior rather than fully adapted — see [ticketing support](/latest/skills/introduction#ticketing-support) for which.
</Note>

<Tip>
  Running more than one orchestrator? Enable the connector for the one you want and disable the other. The session-start check uses whichever orchestrator is enabled.
</Tip>
